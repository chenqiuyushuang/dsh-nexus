# V0.8.3 宽度：面板铺满 iframe + 宽屏双栏

用户问：为什么顶部状态条的宽度和 iframe 一致？为什么面板本体不能和状态条一致？它们对插槽有什么区别？

## 一、原因（实测）

| 元素 | CSS | iframe 418 | iframe 600 | iframe 1000 |
|---|---|---|---|---|
| 状态条 `.status-strip` | 无 max-width，块级，跟着根走 | 418 | 600 | 1000 |
| 面板 `.panel` | `max-width:420px` + overlay `padding:8px` | 402 | 420 | 420 |

结论：状态条铺满是因为它没有宽度上限；面板窄一圈是我自己照抄原型写的 `max-width:420px`（原型是独立窄浮层），
再加上遮罩层 8px 内边距。插槽层面两者没有任何区别——都是同一个 `settings.section` iframe 文档里的普通 div。

## 二、改法

1. `.panel` 去掉 `max-width:420px`（改 `max-width:none`）→ 铺满 iframe；
2. `.overlay` 的 `padding` 8px → 0；圆角/阴影/边框去掉（面板现在就是这一列本身，不需要卡片感）；
3. 宽屏（≥560px）改成两栏：左列表 + 右详情（sticky，展示全文/元信息/动作），窄栏仍单列 + 行内展开。

## 三、实测（改后）

| 场景 | 结果 |
|---|---|
| iframe 418 收起态 | 状态条 x=0 w=418 |
| iframe 418 展开态 | 面板 x=0 w=418（与状态条左右齐平） |
| iframe 900（记忆库页） | 左列表约 46% + 右详情约 54%，详情含全文/元信息/6 个动作 |

## 四、仍然做不到的

面板不能超过 iframe 的宽度（那是宿主 `settings.section` 给的内容列宽度）。
DSH 可用槽位只有 `settings.section` / `settings.action` / `settings.header` / `settings.trigger` / `settings.close` / `settings.onboarding`，
没有任何一个能加宽设置弹窗。要更宽只能用独立页 `/nexus`（铺满浏览器窗口）。
