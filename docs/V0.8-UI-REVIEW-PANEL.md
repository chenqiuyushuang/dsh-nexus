# V0.8 专家团裁决：对《DSH 记忆系统 UI 综合评估报告》的评审

评审对象：一份外部模型基于**单张截图**给出的《DSH 记忆系统 UI 综合评估报告》（自评 9.0/10）。
事实基线见 docs/V0.8-UI-REVIEW-INPUT.md（含实测数据与事实核对表）。
专家团：8 位（视觉 / 交互 HCI / 信息架构 / 数据可视化 / 记忆架构 / 无障碍 / 反方红队 / 产品负责人），
各自独立只读评审，不共享结论。

## 1. 各家评分与一句话结论

| 专家 | 给报告的评分 | 一句话 |
|---|---|---|
| UI 视觉 | 6.5 | 方向对（深色克制、状态色单一来源），但约束理解与证据基础不足 |
| 交互 HCI | 5 | 视觉判断成立，动线全基于误读：P0 的「底部悬浮栏/滚回保存」不存在 |
| 信息架构/文案 | 4 | 唯一有价值的直觉是「术语墙」，但开错了药方 |
| 数据可视化 | 4 | 最抢眼的图连横轴都认错（把条数占比当成配额/token），还据此表扬 |
| 记忆架构 | 4 | 因果全反：两个致命问题（写入判别缺位、注入预算不是主约束）一个没提 |
| 无障碍 | 4 | 建立在忽略可访问性、且漏看两个功能 bug 与 27 条垃圾之上 |
| 反方红队 | 3 | 缺观测纪律：拿未清理的脏库截图当产品现状，不区分真缺陷与脏数据即打分 |
| 产品负责人 | 4 | 第一优先级是「更可信的记忆内容」，不是更好看的界面 |

**均分 4.3/10**（报告自评 9.0）。没有一位专家认可 9.0。

## 2. 专家团一致认定的事实错误（报告）

1. **占比条不是配额条**：它是按作用域的**条数占比**（分母=活跃条数），与 token/配额无关。报告据此发明的「让用户看出谁占用了内存」不成立。（数据可视化 + 红队）
2. **「未进入 31」不是风格问题**：它把 27 条已归档算进了「未进入」，是计数 bug；已修为「未进入 2 / 已归档 27」。（五位专家一致）
3. **0.9/0.95 阈值在截图里根本不可见**：主面板没有这两个数字，它们藏在「设置」展开区。报告在给一个不存在的元素发奖。（记忆架构 + 红队）
4. **「底部悬浮操作栏」不存在**：批量条是**列表上方**的吸顶条，且「已选 N 条」本来就在里面。（HCI）
5. **「滚到底勾选再滚回保存」这条动线不存在**：嵌入态只有列表滚动，保存按钮实测位移 **0px**（本次实测 `staysVisibleOnScroll: {before: 395, after: 395, moved: 0}`）。（HCI，我方实测佐证）
6. **建议美化的 UUID 是污染数据**：`Background subagent 4528e8c3-…` 是子代理回执被误写入的记忆，清理后已不在列表。报告主张「语义化 + 允许重命名」＝给垃圾发精装房，且会让写入门控与噪音识别失去意义。（六位专家一致）
7. **通篇零可访问性**：对比度 30+ 项算术测试、键盘 `/`、Esc 回焦、`role=list/listitem`、aria-live 都是本轮重点，报告一字未提。（无障碍）

## 3. 一致采纳的建议（本轮已实施）

| 建议 | 来源 | 实施 |
|---|---|---|
| 术语「一概念一词」 | IA/文案（P0） | 注入条「N 行」→「注入 N 条」；作用域三处统一为「跨项目/本项目/本会话」 |
| 占比条缺分母/单位、零值不该占图例 | 数据可视化（P0） | 图例跳过 0 值；**在用 < 20 条时不画占比条**，退化成一行文字（含条数与字节预算） |
| 文案折叠按需展开 | 视觉/HCI/产品（P1） | 阈值说明默认收起（省 36px），改为「这两个阈值是什么意思？」 |
| 勾选位移（专家新发现） | HCI（比报告的 P0 更值钱） | 批量条从列表**上方**移到列表**末尾并吸底**：实测勾选后列表位移 **0px**（原来 44px「移动靶」） |
| 只保留可计数/可导航的 chip | IA（P1） | 去掉「降级 否」这类布尔值（真降级时有横幅） |
| 色条只靠颜色传达作用域（1.4.1） | 无障碍（P1） | 亮色改用 ≥3:1 深档 + 折叠行补 `sr-only` 作用域文本 + 新增 6 项非文本对比测试 |
| 「⋯」按钮可访问名不可区分 | 无障碍（P1） | 50 个按钮从「更多操作」改为「更多操作：{主题}」 |
| 撤销 toast 的四个问题 | 无障碍（P0） | 只有文字在 live 区（按钮移出）；悬停/聚焦暂停 5 秒计时；DOM 顺序移到页脚后（Tab 可达） |

## 4. 一致否决的建议

| 建议 | 否决理由 |
|---|---|
| **加大留白与行高（报告 P0）** | 硬约束：设置弹窗 418×448（另有 372×460 档），行高 41px 才换来 6 行列表；加留白＝条目更少。留白只能给宽屏 `/nexus`，不能给 iframe 入口。（八位一致） |
| **「未进入 N」弱化为 Filter Chip** | 它当时是数字 bug；弱化会把错误藏得更深。异常不是噪音，它是用户唯一能发现「记忆没进上下文」的信号。 |
| **UUID 语义化 + 允许重命名** | 美化污染数据；且一旦允许重命名，写入门控与噪音识别失去意义。 |
| **模态框改右侧抽屉** | 设置弹窗属 DSH 宿主、跨文档，插件无权改造；418px 宽里抽屉=全屏遮罩，只增加焦点陷阱/滚动锁成本。（HCI） |
| **「阈值裸露＝透明度/信任基石」** | 透明度的正确客体是**写入判别与注入预算**（为什么没记 / 为什么没进 / 挤掉了谁），不是两个小数；阈值是内部参数。 |

## 5. 专家补充、报告与简报都没提的问题（下一步）

1. **写入判别（什么值得记）是真正的核心**（记忆架构 + 产品）：33 条清理掉 29 条，命中率 ~12%；当前唯一质量信号还是触发词「记住」。建议价值密度门（价值/字节，与 1KB 预算同源）。
2. **可信度闭环缺失**（产品）：治理后的假阳性率、按天摄入量、注入后被引用/回滚率都为空。第一屏该回答「今天写进了几条真东西」。
3. **缩放会复发 B1 的病**（无障碍）：宿主 17px 或浏览器 125–150% 时，chip 11.5px、按钮/下拉 12px 仍是硬编码 px，工具栏退回 3–4 行；固定高 flex 列 + 列表 min-height 会顶破 620px 上限，头部随外层滚走。**未修**。
4. **注入预算应成为主约束**（记忆架构/数据可视化）：列表行显示字节、可展开「字节排行」，让「新增记忆＝挤掉谁」可见。**未做**。

## 6. 主持人的判断

报告的**措辞质量高、观察力强**（术语墙、留白、动线这些词都抓得准），但它犯了三个方法论错误：
① 拿一张**未清理的脏库截图**当产品现状，不区分「真缺陷」与「脏数据」；
② 用**视觉隐喻**替代数据核对（把条数占比当配额条、给不存在的阈值控件发奖）；
③ 给出 **9.0** 这种精确到小数点的总分，却没有一项阈值、样本或复现步骤。

它对的地方我已采纳（术语统一、文案折叠、只留可计数 chip）；它错的地方已用实测数据驳回（留白/行高、Filter Chip、UUID 美化、抽屉）。
**真正重要的问题它没看到**：一个 UI 好不好，先看它显示的数字是不是真的 —— 这一点上，它给 9.0 的那个界面当时正在显示「未进入 31」和 27 条垃圾。

综合判断：**报告 4/10；本产品当前 UI 6.5/10**（工具合格、内容可信、仍不够好看）。

## 7. 本轮实施清单（可核对）

- 注入条单位统一 + 分组标题带「条」
- 占比条：0 值不进图例；在用 < 20 条时退化为文字摘要
- 阈值说明默认折叠
- 批量条移到列表末尾吸底（勾选零位移，实测 0px）
- chip 去掉布尔值；筛选器/行标签/占比条三处用词统一
- 色条亮色 ≥3:1 + 折叠行 sr-only 作用域 + 6 项非文本对比测试
- 「⋯」可访问名带主题
- toast：live 区只含文字、悬停/聚焦暂停、DOM 顺序与视觉一致
- 测试 287 通过 + 5 xfail（新增 6 项非文本对比）
