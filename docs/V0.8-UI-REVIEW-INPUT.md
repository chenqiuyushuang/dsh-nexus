# V0.8 外部 UI 评估报告 —— 事实简报与待评审原文

评审对象：一份外部模型基于**单张截图**写出的《DSH 记忆系统 UI 综合评估报告》（评分 9.0/10），
外加它给出的 P0/P1/P2 改进建议。用户要求：专家团评论这份报告。

## 0. 评审纪律
- 一切判断以本文件的事实为准；截图上看不出来的东西不要推断。
- 允许并鼓励指出「报告说错了」。
- 结论必须可执行（给出改什么、不改什么、优先级），不要只谈感受。

## 1. 系统是什么
Nexus 是 DeepSeek Harness 的记忆插件：本地存储（~/.dsh/nexus），零配置默认，
会话内自动注入 ≤1KB 的记忆块，面板挂在 DSH「设置」弹窗的第 5 项（iframe，窄栏），
另有独立页 /nexus（宽屏）。设计约束写在 docs/V0.7-PANEL-DESIGN.md。

## 2. 实测事实（全部由无头 Chrome 量出，非估算）

| 场景 | 尺寸 | 结果 |
|---|---|---|
| 宽屏独立页 | 1080×557 视口 | 行高 41px · 行距 47px · 首屏 6 行（700px 视口约 9 行） |
| 设置弹窗（暗色） | 418×448 | 注入条 43px · 工具栏 2 行 · 列表 291px / 6 行 |
| 修复前（同一尺寸） | 418×448 | 注入条 **6px（整条消失）** · 工具栏 4 行 108px · 列表 66px / **1 行** · 页脚 63px（比列表还高） |

今天修掉的真问题（都有测试或实测证据）：
1. flex-shrink：`.nx-app` 是 flex 列，只有列表设了 `flex:1`，注入条带 `overflow:hidden` → 自动最小高度 0 → 在窄栏被压成 6px，**核心信息消失**。
2. 高度上报自我锁定：面板用 `documentElement.scrollHeight` 上报，而 `.nx-app` 是 `height:100%` → 恒等于当前高度 → 永远只申请「维持现状」。改为按内容申请后 448 → 562。
3. 「未进入 31」语义错：`dropped` 把已归档的 27 条也算进去了；清理后用户看到这个数字以为没生效。现拆为「未进入 2 / 已归档 27」。
4. 一键清理后列表仍显示「全部状态」→ 27 条垃圾还在眼前。现自动切「活跃」。
5. 写入侧污染：DSH 把子代理/后台任务回执当 user 消息注入父会话，Nexus 当成用户陈述存下（实测 33 条里 22 条）；另有 6–7 条 2KB 提示词被写成记忆。两条路径已堵。
6. `stripTrigger` 用全局替换删触发词 → 存进库的句子和用户原话不一致（「记住：发布前必须记住检查」→「发布前必须检查」）。

## 3. 记忆库现状（用户已点过「一键清理」）

## 4. 事实核对表（报告的说法 vs 实际）

| # | 报告的说法 | 实际 |
|---|---|---|
| 1 | 顶部进度条是「记忆配额」，「让用户一眼看出是谁占用了内存/token」 | 它是**按作用域的条数占比**（清理后仅 3 条：用户 1 / 项目 2），与 token、配额无关；条数很少时信息量极低 |
| 2 | 「底部的悬浮操作栏（已选 2 条…）」 | 是列表**上方**的吸顶批量条（sticky top），不是底部；它建议改成吸底并「把已选状态也整合进去」——已经是这样 |
| 3 | 「裸露 0.9/0.95 阈值是透明度优势，是信任基石」 | 与既定设计冲突：V0.7 设计定的方向是**配置面收敛到约 3 个旋钮** + `/memory doctor`；阈值对普通用户是纯噪音 |
| 4 | 「未进入 31」标签太扎眼，建议弱化成 Filter Chip | 它是 **bug**（把 27 条归档算进未进入），不是风格问题；已修为「未进入 2 / 已归档 27」 |
| 5 | 建议把 `Background subagent 4528e8c3…` 语义化成「[图标] 后台子代理 …9a3f」，甚至允许重命名 | 这些是**被污染写入的垃圾**（子代理回执），清理后已不在列表里；美化垃圾数据是错的方向 |
| 6 | 建议「增加留白、增加行高」（P0） | 与硬约束冲突：设置弹窗只给 ~448px，行高 41px 时列表才 6 行；留白加大 = 可读条目更少。宽屏可以给留白，窄栏不行 |
| 7 | 通篇未提可访问性 | 对比度/键盘/读屏是这轮重点：30 项对比度算术测试（亮暗各 15 组 ≥4.5:1）、jsdom 焦点测试、「/」聚焦、Esc 回焦、role=list/listitem、aria-live |
| 8 | 综合 9.0/10「专业工具领域上乘之作」 | 同一张截图上至少有 2 个功能性 bug（注入条不可见、徽标数字错误）+ 列表里 27 条垃圾。分数缺依据 |

## 5. 待评审原文（要点重述，避免贴全文）
- 亮点：深色克制、圆角胶囊、占比条「神来之笔」、批量条即时反馈、暴露阈值=透明度
- 痛点：术语墙 + 说明文字过小过灰、信息密度窒息缺留白、保存按钮权重低、未进入 31 太突兀、UUID 直出、操作动线长（滚到底勾选再滚回保存）、模态框切断上下文
- 建议 P0：保存按钮吸底 + 已选状态并入底栏；加大间距与行高
- 建议 P1：文案折叠 + (?) tooltip；UUID 语义化；异常状态弱化为 Filter Chip（[全部][活跃 4][待处理 31]）
- 建议 P2：简易模式/专家模式渐进披露；模态框改右侧抽屉 + 高亮当前对话引用的记忆
