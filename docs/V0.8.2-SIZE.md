# V0.8.2 面板 B 的尺寸：宽度是硬约束，高度已修

用户问：「点击进去之后是不是太小了？宽度和高度？」

## 一、宽度：不是我们能决定的

DSH 的设置弹窗给插件内容区的宽度是固定的（实测 **418px**），面板是 `width:100%` 铺满它。
两版截图里面板都是 418 宽，与设置弹窗内容区等宽 —— 也就是说**宽度已经用满了，没有再宽的空间**。
要更宽只能改 DSH 的设置弹窗布局（用户定的红线：不改 DSH 源码）。

对照：用户给的样例 HTML 是 780px 宽的独立弹窗，所以同一套样式在 418px 里必然显得更挤。
独立页 `/nexus`（浏览器直接打开）是全宽的，那里是样例的比例。

## 二、高度：之前确实浪费了，已修

面板通过 `postMessage` 告诉宿主 iframe 该多高。这段逻辑原来只认旧面板的选择器
（`.nx-app`/`.nx-list`），面板 B 里这两个类**一个都没有** → 期望高度恒为 168px，
宿主只好用 `minHeight:480` 兜底。结果：

- **收起态**（只有一条 43px 的状态条）也占满 480px，在设置页里留一大块空板；
- **展开态**拿不到按内容算的高度，只能挤在宿主给的槽里。

### 修法

1. `desiredHeight()` 增加面板 B 分支：收起态报「状态条高 + 8」（实测 **51px**），
   展开态报「面板 chrome + min(内容高, 6 张卡)」，上限 620。
2. iframe 的 `minHeight` 从 480 降到 48（收起态不再白占半屏），`maxHeight` 仍是 620。
3. 宿主把可用高写进 `--nx-b-available`，遮罩层用它算 `max-height`（比 92vh 准，不受 iframe 当前高度影响）。

### 实测（418 宽）

| 状态 | 上报高度 | 说明 |
|---|---|---|
| 收起 | **51px** | 只剩状态条（原来 480） |
| 展开 | 到 **620** 为止 | 面板内 570px 可视内容区，其余内部滚动 |

用户在设置弹窗里看到的可用高由宿主决定（截图里约 448px），此时面板展开后占满整列并内部滚动。

## 三、还剩的空间问题（下一轮）

- 内容区在 448 档只有约 316px（面板 chrome 95px 已是最小）；要继续扩容只能再减 chrome，
  候选：模式三态并进标签行、分组头进一步压缩（两者合计还能省 ~30px）。
- 更根本的办法是让 DSH 的设置弹窗给更宽的列（上游功能请求），或在独立页 `/nexus` 里用。
