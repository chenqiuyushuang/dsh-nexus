## 3. 分歧与我的反驳（辩证）

**D1 红队：「砍掉 LLM 通道 + 语义层 + 面板，只留 30%」**
- 反驳：①面板是**唯一纠错面**（用户已实际用它置顶/归档/查看决策日志），砍掉等于把"看得见、改得动"重新变成黑盒；②语义层的极性 ×0.2 与冲突检测正是为了阻止"相反记忆同时注入"（有实测：曾同分 1.0），砍掉是回到已证实的错误行为；③LLM 通道**默认关闭**且有双闸（每会话 8 窗、每日 20 万 token），成本风险已被约束，而它提供的语义覆盖是规则层做不到的。
- 但我**接受**其核心：`vector`（5 位专家独立主张砍）、`integrator`、`skill-compiler`、`embedding` 死字段、`lib/nexus-ui.js` 全部进删除清单（已删最后一项，面板 700KB → 178KB）。

**D2 上下文工程：「改成每轮按需注入 top-3，身份/pinned 走 systemPrompt.section」**
- 接受：**compaction 后必须重注入**（真实缺陷：长任务摘要后记忆静默消失）。
- 反驳：①"每轮检索注入"把成本从 O(会话) 变成 O(轮)，与用户最核心的诉求（不烧 token）直接冲突；②把记忆放进 `systemPrompt.section` 会**提高**它在模型眼里的权威性，与我们刚建立并测试过的"记忆是数据不是指令"原则相悖。折中：保持 user 消息通道 + **事件驱动重注入**（compaction/会话恢复），不改为每轮。

**D3 成本：「日限只值 $0.03–0.06，该放宽/砍掉」**
- 反驳：预算目标不是省钱，而是**可预测性**——用户明确问过"记忆多了是不是很费 token"，一次"账单对不上"比多花几美元更伤信任；且真值记账后总额本身会下降（现在 output 恒记 0 是低估）。
- 接受：真值记账（provider usage）+ **原子预留**（防并发越闸）+ output 计入日限 + 面板显示本月花费与上限。

**D4 HCI：「面板 pending/conflicts 恒 0，回收站是假的」**
- 反驳：pending/conflicts 计数**本轮已修**（`web-ui.ts:43-48` 改为对全量统计），专家读到的是修复前版本；"彻底清除"也已在 `882c049` 落地。
- 接受其余：补 `deleted` 态（区分"用户删的"与"系统归档的"，恢复只允许前者）、墓碑只存 fp 不存整句、置顶的预算占用提示。

**D5 存储：「多进程无锁 → purge 被复活、setState 互相覆盖」**
- 接受方向，但反驳其可行性判断：DSH 的 storage domain 是用户级共享且无 pid 锁，插件在**单进程内**做原子预留可解决提炼并发；跨进程一致性需要 domain 层支持（列为 P1，附"D-3 已在本轮修 pruneCosts 方向"）。

**D6 内核：「硬 inject 反噬 fail-open」**
- 接受（P1）：`inject` 里任一服务缺失会让 apply 永不执行；改法是把 `sessions/agents/tools/commands/sessionProjections` 换成 `ctx.inject([...], cb)` 惰性接入，`storageDomain` 保留为硬依赖。

## 5. 行动项（P0 → P1 → P2，每条带验收）

**P0（下一批，必须做）**
1. **生命周期 tick**：weight 衰减（pinned/身份/偏好免疫）+ episode TTL + recall 裁剪调度；验收：5000 条跨 30 天模拟下新记忆仍进索引，`nexus/memory/decayed` 事件有 golden。
2. **真值记账 + 原子预留**：provider usage 回填、output 计入日限、并发预留；验收：并发 K 会话上限=1 窗时 Σ≤cap；`/memory cost` 的 output 随调用变化。
3. **分层评测集进门禁**：≥200 条真实语句（负例 ≥50%）+ 20 条无关查询 + 10 组跨项目对；输出 durable P/R、scope 正确率、P@5/R@5；验收：无关查询召回=0，漂移 ±2% 变红。
4. **BM25 排序**（IDF + tf 饱和 + 长度归一，零依赖，复用 prepared 缓存）；验收：holdout ≥50 条 + nDCG@6 ≥0.8。
   - 进度（诚实）：IDF 稀有度加权已落地（`6708817`），但**未解决**多主题长查询错排——实测「数据存哪里 + 会不会每次重注入」top-1 仍是字面重复查询词的原子，P@5 持平 0.487。tf 饱和 + 长度归一 + 字段权重仍未做；**多主题长查询的天花板可能需要语义层（查询拆解/embedding）而非纯字面排序**。

**P1**
5. compaction 后事件驱动重注入（golden +3 例）。
6. `deleted` 态与回收站视图；墓碑只存 fp；恢复仅限用户删除项；置顶预算提示。
7. 配置面收敛：默认只留 3 个旋钮；未知键加载告警；`deterministic` 枚举合并；`/memory doctor`。
8. 惰性 inject 接入（`ctx.inject`）替代硬依赖；`webServer.register` 用 `ctx.effect` 托管（修 live-reload duplicate route）。
9. 存储：`global.json` 自愈（备份+回落+warn）、`compatibleVersions` 声明、purge 与多进程一致性方案。
10. npm 发布 + GitHub topic `dsh-plugin` + tag 与版本对齐 + CI 加 pnpm 安装矩阵。

**P2**
11. 时态化（validFrom/validTo/supersededAt + 编辑快照，「某时点我们相信什么」）。
12. 简繁折叠 + 语气词归一（xfail-03/04 转正例）。
13. 处理不确定语用：选择问/引述/反问默认 pending 交人（而非猜）。
14. 面板：会话小结展示、回收站视图、成本面板（本月花费/上限）。
