# Nexus 面板设计定稿（v0.7 UI 专家团 · 7/7 回收）

> 输入：7 位 UI 专家独立只读评审（信息架构 / 交互 / 视觉 / 可访问性 / 信任与可解释性 / 数据密度 / 窄屏与 iframe）＋主持人第 8 票
> 结论：**7/7 一致「需要重构，但不必推倒」** —— 数据层、路由、组件、token 全部可复用；病根是布局契约、客户端过滤、动作过载、反馈缺失、注入真相不可见。

## 1. 专家共识（7 位独立命中 → 全部采纳）

| # | 共识 | 代表证据 |
|---|---|---|
| 1 | **布局契约坏了**：宿主 iframe 初始 480px，面板回传无上限 scrollHeight；头部 236px 滚走；真实可用宽 **564px（窄屏 356px）** 而非 640 | 窄屏专家实测 sticky 0 处、SettingsRoot.module.css:221 |
| 2 | **过滤在错误的一层**：API 无 status 参数 + limit 截断后才前端 filter → chips 报 2 条冲突、列表可为 0 | IA + 密度专家（实测带 status 与不带参数响应完全相同） |
| 3 | **动作过载**：单行 6-9 个按钮（5-7 个 Tab 停靠点 × 80 行 ≈ 400-560 个），三种删除并排，红色按钮 2 个 | 交互 + 视觉 + a11y |
| 4 | **注入真相不可见**：33 条里 29 条单行超过 1024B 永远进不了上下文，11 条 projectRef 为 unknown 永不注入，面板只显示「活跃 31」 | 信任专家（对拍 MEMORY.md 与 buildIndex） |
| 5 | **反馈层缺失**：post() 丢弃响应、成功零提示；window.confirm/alert 脱离 iframe；批量后端已支持 ids[] 前端未接 | 交互 + a11y |
| 6 | **撤销是假的**：restore 不清黑名单 → 恢复后同句仍被静默拒收 | 交互 + 信任（已修，见第 4 节） |
| 7 | **a11y 四项全缺**：键盘 0 处、焦点丢 body、无 aria-live、5 处对比度不达标（2.15-3.76:1） | a11y（WCAG 实测） |
| 8 | **视觉层级失效**：作用域/槽位/状态共用一批色；暗色下三类胶囊与行底同色消失；单行 144px → 首屏仅 2.9 条 | 视觉（盒模型推算） |

## 2. 定稿结构（线框）

    +-- 记忆 -------------------------- [为什么没记] [设置] --+   <- sticky 0
    | [待办 3] [全部 31] [回收站 5]                            |   <- tabs，计数即导航
    | [搜索...]  作用域v  状态v  排序v              [+ 新增]   |   <- sticky 44
    | 注入 931/1024B ========== 91% · 置顶 2 · 挤掉 27   (i)   |   <- 注入真相，可点开分组
    +-------------------- 唯一滚动区 -------------------------+
    | [ ] | 待确认   仅本项目·个人                    09-11     |
    |     本周只跑 vitest，不跑 e2e（3 行折叠，点击展开）       |
    |     [确认] [编辑] [更多]                                  |
    | [x] | 活跃     跨项目·偏好                                 |
    +----------------------------------------------------------+
    | 已选 2 · [确认] [归档] [移入回收站] · 清除选择             |   <- 批量条
    +----------------------------------------------------------+
       抽屉：决策日志（每条 [就记住] [定位到列表]）
       toast：「已移入回收站 2 条 · 撤销 5s」

**关键设计点**：作用域用左侧色条 + 文案（「仅本项目 / 跨项目」），状态用圆点 + 颜色（唯一给颜色的东西）；槽位降为 11.5px 灰字；ID/权重/置信/时间移入展开区；危险动作全部收进「更多」，每行红色按钮 ≤1。

## 4. 评审期间已落地的后端前置

| 改动 | 依据 |
|---|---|
| memory 路由新增 status / reviewNote 服务端筛选 + limit ≤500 | IA / 密度（实测参数不存在） |
| state 路由新增 trash / archivedBySystem / injection（budgetBytes, lines, omitted, pinned） | 信任（注入真相）+ IA（计数即导航） |
| restore：只恢复 user-deleted 条目，并**连带删除黑名单记录**（真撤销） | 交互 + 信任（实测撤销是假的） |
| purge：只允许从回收站彻底清除（系统归档不可被清除） | 交互 + IA（回收站是唯一真删闸门） |
| 测试：回收站三态语义 + 服务端筛选 + 注入预算字段；206 通过 + 5 xfail | — |

## 5. 不做（专家一致或主持人否决）

- 不换 UI 框架 / 不引入组件库（违背零依赖单文件构建）；
- 暂不上虚拟滚动库（先用 content-visibility，1000+ 条实测后再谈）；
- 决策日志放抽屉而非独立 Tab（实测高频再改）；
- 不表格化列表（记忆是自然语言句子，卡片 + 折叠更合适）。

## 6. 落地时的规范修正（主持人裁决，2026-09）

| 原规范 | 修正 | 原因 |
|---|---|---|
| B2：列表 `statement` 截 400 | 列表截 400 **但编辑/缩短前必须调 `/nexus/api/memory/get?id=` 取全文**；点击编辑时载入，截断行显示「全文 N 字」提示 | 本机实测 29 条记忆 >1024B、中位数约 3.2KB。若编辑器照列表内容载入再保存，会把后面 2.8KB 静默删掉 —— 这是数据丢失，不是性能优化 |
| B2：`items+total` 一次给全 | 面板按 80/页请求，「加载更多」用 `offset` 追加；筛选（q/scope/status）全部走服务端 | 此前前端拿 80 条再本地过滤 → 库 >80 时「待确认」筛出 0 条且 chips 与列表不一致 |

验收证据：`tests/web-ui.test.ts` 的 B2 两例（分页/上限/末页、投影字段/截断长度/全文/404）+ 面板渲染 2 例。
