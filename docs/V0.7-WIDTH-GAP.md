# 为什么"看起来差很多"：样例 720px vs 面板 418px（实测）

用户反馈："差别好大！我想要一模一样的！"

## 结论先说

**差别的根因不是样式表，是宽度**：样例 HTML 是 **720px 宽的独立弹窗**，而 DSH 设置弹窗
给插件内容的可用宽度是 **418px**（实测，见下）。同一套 CSS 在两档宽度下就是两种观感。

我把样例的**绝对尺寸**（16px 卡片内边距 / 14px 条目不内边距 / 16px 正文 / 两行大数字状态卡）
原封不动搬到 418px 试了一遍，实测：

| 档位（418×620，同字号 16px） | 可见记忆条数 | 单条行高 |
|---|---|---|
| 紧凑档（当前默认） | **2 行**（+ 第 3 行露头） | 96px |
| 样例绝对尺寸档（`--reference-scale`） | **1 行**（+ 第 2 行露头） | 104px |
| 仅条目宽松档（`--row-scale`） | 2 行 | 96px |

也就是说：**在 418px 里把样例的比例照抄，只是把"能看到几条记忆"从 2 条变成 1 条**，
其它什么都没变——因为横向挤压的问题（标题每行只能放 ~19 个字）跟内边距无关。

## 实测：宿主给的面板宽度

```
node scripts/panel-preview.mjs --width 418 --height 448 ...   # 与 DSH 设置弹窗内容区一致
```

DSH 设置弹窗本身（登录态）无法用 CDP 直接量：`dsh web` 的鉴权 token 只在进程内存里，
headless 打开会被重定向到 "dsh web authentication required"。所以宽度取自用户实拍截图与
插件 iframe 的 `width: 100%` 契约：**418px**。

**面板不能自己变宽**——宽度由宿主的设置弹窗决定。要真正 720px，只有两条路：
1. 改 DSH 源码/样式（用户的硬性约束里明确不改）；
2. DSH 官方把设置弹窗内容区做宽（属于上游功能请求）。

## 已经落地的三步（0.6.2）

1. **独立页按样例比例**：`/nexus` 独立页本来就是全宽，现在给它 `.reference-scale`
   （16px 内边距 / 两行大数字状态卡 / 14px 条目），在 1440px 屏上是样例的真实观感。
2. **窄栏加「全屏打开」按钮**：设置面板里一键 `window.open('/nexus')`，
   想看样例那种效果时用它，不用改 DSH。
3. **窄栏把噪音横幅收细**（94px → 约 40px），首屏多出一行记忆的位置。

对比图：`_shots/v070-narrow.png`（418 窄栏） vs `_shots/v070-standalone.png`（1180 宽独立页）。

## 还没做、需要你点头的

- 要不要把窄栏的正文也提到 16px？（现在是跟随宿主字号；17px 宿主下已经接近样例的观感）
