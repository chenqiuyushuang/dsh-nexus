# 0.8.8 起：独立端口 + 真浏览器 + DevTools 协议 的调试方式（采纳用户建议）

用户提议：改完另起一个端口测试、用浏览器 + 开发者工具调试。**这是对的，而且立刻抓出了两个我在预览壳里看不见的 bug。**

## 一、怎么起（一条命令）

    npm run debug:web            # 默认端口 3199，自动用 open 打开带 token 的地址
    npm run debug:web -- 3201    # 换端口

脚本 scripts/debug-web.sh 做三件事：
1. 用 **workspace 内的 DSH_HOME**（_dsh_test）启动，和用户的 3080 实例完全隔离（自己的 store / 会话 / 日志）；
2. 自动把最新 tarball **热替换**进调试 profile 的 node_modules/@chenqiuyushuang/dsh-nexus（不跑 pnpm，避免 store 版本不一致）；
3. 从日志里抓出带 token 的地址打印并打开。

日志：_shots/debugserver.log（里面 dsh web: http://127.0.0.1:3199/?token=… 那行就是入口）。

## 二、程序化调试（CDP = 开发者工具同一套协议）

scripts/debug-real.mjs：headless Chrome 连上调试实例 → 关掉内测声明 / API Key 引导 →
点「设置」→ 点「记忆」→ 量 iframe 与面板的几何与计算样式 → 截图。

    node scripts/debug-real.mjs

产出：_shots/real-01-closed.png、_shots/real-02-open.png，以及一行 JSON 测量。

## 三、真机与预览壳的差别：两个只有真机能抓到的 bug

1. **根节点从来没有 .panel-open 类** —— 「统一表面」的 CSS（背景/圆角/边框）写了却从没生效。
   预览壳量的是面板内部元素，panel-open 只影响根节点外观，截图里看不出「该有而没生效」。
2. **展开时 iframe 只报 471px，而设置弹窗有 800px** —— 预览壳写死 iframe 尺寸，desiredHeight() 的上报值被忽略。

两个都修了：
- 根节点 className 加 open ? ' panel-open' : ''；
- 面板打开时 desiredHeight() 直接返回宿主可用高（不再按「内容最多 6 张卡」算），iframe 上限 1000 → 2000（宿主仍按自己的可用高裁剪）。

## 四、真机实测（设置弹窗 800×800）

| 状态 | iframe | 根节点 | 面板底 | 内容区底 |
|---|---|---|---|---|
| 收起 | 564×51 | 59（只有状态条） | — | — |
| 展开 | 564×**764** | 764×556，背景 #131316 / 圆角 8px / 边框 1px #33333A | **764** | **764** |

面板底与内容区底都等于 iframe 底（无空档），并与「Agent 预设」同高（弹窗内可用高）。

## 五、以后怎么用

- 每次改完 UI：npm run build && npm pack && npm run debug:web（脚本会自动装最新 tarball）→ 浏览器里手动看，
  必要时 node scripts/debug-real.mjs 出测量与截图；
- 这比只跑 panel:preview 强：预览壳能覆盖窄栏 / 宽屏 / 主题，但**宿主弹窗的真实高度与容器宽度只有真机能给**。
