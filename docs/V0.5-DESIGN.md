## 一、四条不可动摇的原则

> ⚠️ **本项目共有三组「不可动摇的原则」，条目互不相同**：本文这四条 /
> `NEXUS-DESIGN.md` §1 的四条（好用为王 · 不烧 token · 辩证看方案 · 借鉴验证过的骨架）/
> `README.md` 的三条（数据与指令分离 · 零配置默认零成本 · 写入宁缺毋滥删除可回溯）。
> 三组都还在，尚未收敛；引用时请写明出处。

1. **数据与指令分离**：记忆永远是数据。注入块有声明、内容被扁平化、扫描器拦截指令型写入。
2. **零配置默认零成本**：默认档不调用任何模型（0 token / 0 网络）；一切增强都显式开启。
3. **写入宁缺毋滥，删除可回溯**：系统自动只归档；用户显式删除走回收站；任何"记住"都能一键撤销。
4. **无度量不上线**：每个机制都要有指标 + 回归测试，否则就是"写了没人读"的死机制（本项目已犯过 8 次）。

> **实现状态**（2026-09 复核）：#1 与 #2 属实；#3 的「只归档」属实，但回收站的**实现表示法与 D4 的设计不同**；
> **#4 部分修复** —— 死代码只剩 `linkCluster`（全仓零调用点），`runLifecycle` 已在 0.8.9 接到写入路径的
> `Facility.tickLifecycle()`；「零测试引用的模块」共 10 个，**清单不写死在这里**：
> 由 `npm run docs:status` 现算并写进 `IMPLEMENTATION-STATUS.md` 的独立小节（写死数字下次增删模块就又过期）。
> 这也是 `docs/DOC-MAINTENANCE.md` 那套「文档状态门禁」的起因。

## 二、六项定稿决策

### D1 写入：双通道，职责分明

| 通道 | 触发 | 成本 | 入库状态 | 何时可见 |
|---|---|---|---|---|
| **A 即时规则** | 「记住 X」/身份/偏好/硬拒 | 0 | 直接 active（user-declared 0.98） | 当场；下一轮注入刷新后进块 |
| **B 会后 LLM** | 会话结束 1 次 | 按预算 | 置信 ≥0.95 → active；0.5–0.95 → **待确认**；<0.5 丢弃 | 下次会话（active）或面板（待确认） |

**取舍**：放弃"LLM 实时逐轮提炼"（每轮烧钱、且用户在会话中根本来不及看）；换取成本可预测。代价是**本会话内看不到 LLM 成果**——用通道 A 兜底。

### D2 提炼时机：三档，默认中间档

| 档位 | 行为 | 适用 |
|---|---|---|
| `off` | 只走通道 A | 极简主义者 / 纯本地小模型场景 |
| `session-end`（**默认**） | 会话结束按 `windowBytes = maxInputBytes - 开销` 分窗，每会话窗数 ≤ N、每日 token ≤ T | 绝大多数人 |
| `checkpoint` | 每 N 轮或累计 B 字节提炼一次（**需护栏先落地**） | 长任务，希望本会话受益 |

> **实现状态**：⚠️ **档位名与实现不同**。代码里的 `extract` 取值是 `deterministic | reminder | off`，
> 默认 `reminder`（`src/config.ts:154`）；`session-end` 与 `checkpoint` **在代码里都不存在**。
> 「分窗 + 每会话窗数 ≤ N + 每日 token ≤ T + 超限跳过并记账」这部分是**已实现**的（`src/budget.ts:63-80`，默认 8 窗 / 20 万 token）。
> 注意 `reminder` 只是档位名：LLM 是否真的被调用，取决于有没有配置 `extractorLlm`（默认没有 → 零 token 档）。
> 「CHECKPOINT 未做」这一项后来在 `docs/V0.6-PANEL-BRIEF.md:42` 被再次承认。

**取舍**：放弃"长任务中途即时受益"，换取预算确定性；`checkpoint` 作为显式选项保留。**同一会话内绝不重复提炼同一段文本**（窗口游标持久化）。

### D3 注入：混合模型（索引 + 增量 + 按需）

1. **首轮注入一次** ≤`indexBudgetBytes`（默认 1KB）的索引块，块头写「注入 N/M 条（其余用 /memory search）」；
2. **会话中只发增量**（新入库记忆 ≤200B），不重发整块（prefix 友好、成本可预测）；
3. **按需检索**：模型可 `memory_search`（返回 ≤1.5KB、topK 可配），命中的记忆才算"被用到"；
4. 排序：`pinned > weight > 最近更新`；身份/偏好永远优先入选。

**取舍**：放弃"每轮全量注入"（30 轮 ≈30KB 重复块，破 prefix cache）；也放弃"零常驻"（模型不主动搜就完全没有记忆、且失去唯一可审计面）。混合方案两头都保住，代价是**注入块只能覆盖 ~10 条**——用块头声明 + 置顶 + 按需检索弥补。

### D4 生命周期：墓碑化 + 强度，不硬删

- 系统路径（去重/冲突/过期）**永远只归档**（`status: archived`）；
- 用户删除 → **回收站**（~~`status: deleted` + `deletedAt`~~ → 实际是 `status: 'archived'` + `reviewNote: 'user-deleted'`，注入/检索/默认视图全排除）→ ~~7 天或~~二次确认后「彻底清除」才真删并清理 `edges`（7 天定时清除已撤销，见下）；
- 删除同时写 **reject 墓碑（fp）**，同句重提不再复活；
- 强度：`weight` 随"被检索命中 / 用户确认"上升，随时间衰减；`pinned`、身份、偏好**免疫衰减**；衰减到阈值 → 冷归档（不注入但可搜）。

> **实现状态**（2026-09 复核）：三处与实现不同，一处已修。
> ① **没有 `status: deleted` 与 `deletedAt`**（状态枚举只有 5 个值；0.8.9 起这两个符号本身也从 schema 删除了）。回收站的实际表示是 `status: 'archived'` + `reviewNote: 'user-deleted'`（`src/web-ui.ts` 的 trash 计数与列表路由）。
> ② 🗑️ **7 天定时清除不做了（承诺已撤销）**：时间驱动的自动清除不可逆，与 §一.3「删除可回溯」直接冲突 —— 按 Q2 两边一起删，不再当欠债。保留的是面板「彻底清除」的二次确认，且它只在 web 路由（`/nexus/api/memory/purge`），README 列的 `/memory purge` 命令实际**只归档**。
> ③ 墓碑**按归一化 statement 比对而不是 `fp`**，且只有 `user-reject` 一类墓碑会拦。
> ④ ✅ **已修（0.8.9）**：`memory_feedback` 的 `bad` 真的降权、且不再刷新 `updatedAt`（刷新会让它看起来更新鲜，反而在注入排序里往前挤）；衰减由写入路径的 `Facility.tickLifecycle()` 驱动 —— `runLifecycle` 此前全仓零调用点，所以「随时间衰减」曾经真的没发生。

**取舍**：放弃"真删即解脱"（记忆是资产，误删不可逆），也放弃"永不删"（隐私权要求）。两段式是唯一同时满足两者的方案，代价是**多一次点击**。

### D5 安全边界：本地优先，默认严格

- 写操作：`Origin` 必须存在且与 `Host` **精确相等**（含端口）；
- 读操作：`Host` 必须是 loopback 字面量（127.0.0.1 / localhost / [::1]）——挡 DNS rebinding；
- 远程访问：默认禁止，需显式 `webuiAllowRemote: true`（放开后只做 Origin==Host 精确匹配）；
- 注入块：声明"数据非指令" + 内容扁平化；密钥/身份证/私钥出厂扫描；`~/.dsh/nexus` 文件 0600。

**取舍**：放弃"远程开箱可用"（安全默认优先），代价是远程用户要改一个配置项。

### D6 质量门：golden 集先行

- ~~`bench/golden.jsonl`：今日 12 个 bug 的最小复现 + 同族泛化 50 条 + 负例 30 条 + 作用域隔离 20 条~~：🗑️ **承诺已撤销**（该文件不存在，实际形态见下）；
- CI 两层：**L0 确定性**（无网络无 LLM，必须全绿才合并）/ **L1 回放**（模型输出存盘后确定性重跑，只报趋势）；
- 指标线：写入 P≥0.9 / 误记≤2% / scope≥0.98 / 残留=0；检索 Recall@5≥0.9、MRR≥0.75、假阳≤5%；注入命中≥0.6、每会话 ≤1 次。

> **实现状态**：⚠️ 三项都按「要么做、要么撤销承诺」收敛完毕。
> ① **`bench/golden.jsonl` 文件不存在，承诺已撤销**：实际是 `tests/golden.test.ts` 内联 **22** 例（12 条 bug 复现、5 条泛化、5 条负例），文档已写明实际形态。补到 112 条的成本高于收益。
> ② **CI 没有 L0/L1 两层，承诺已撤销**：`.github/workflows/ci.yml` 是单 job、六步（typecheck / test / docs:check / build / check:pack，以及构建前的检查）——没有回放层，也没有持久化的模型输出夹具。文档已写明「不做」。
> ③ **9 条指标线收敛为 4 条可测的**：现在 CI 强制 —— 写入精确率 **P≥0.9**、**误记率≤2%**、**scope≥0.98**（三条都在 `tests/golden.test.ts` 用金标集算）与检索 **Recall@5**（`bench/holdout.ts` 门槛 0.8）。其余 5 条（残留、MRR、假阳、注入命中、每会话次数）**没有数据源，已删除**，不再当门面。
> 另外：本文 D6 的取舍写「放弃先加功能再补测试（今天 12 个 bug 全部逃过 134 个单测）」。当前套件 **34 文件 / 398 用例**（2026-09 实测），`tests/golden.test.ts` 里仍有 **4 条 `it.fails`**（已知未修，修好会自动翻转提醒）—— 「L0 必须全绿」实际是带着已知失败变绿的，这一点如实写在这里。

**取舍**：放弃"先加功能再补测试"（今天 12 个 bug 全部逃过 134 个单测的教训）。

| 可见性 | `/memory cost` + 面板实时显示 bytes 与估算 token；会话小结提示"本次记 N 条 / 跳过 M 窗" | 同 |
