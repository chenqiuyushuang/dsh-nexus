## 发现 1（P0，待修）：展开注入条会把头部挤出视口

实测：`--expand-inject` 下 `panelReportedHeight = 620`（上限）而文档高 **1345px，溢出 725px**。

- 根因：`desiredHeight()` = 非列表区块高度 + 列表期望高度，再 `min(desired, cap)`；而**上限 620 是硬顶**。
  注入条展开后「非列表区块」从约 180px 涨到约 700px（已进入 2 条 + 未进入分组 + 说明），
  chrome + list 远超 620 → 内容在 iframe 内溢出 → **头部随外层滚走**（B1 修过的病以另一种形态复发）。
- 影响：用户在窄栏里点开「为什么」看注入真相，滚两下标题与状态条就没了；到 620px 以上还会把设置弹窗顶出滚动。
- 建议修法（下一批）：给展开区自己限高 + 内部滚动，与行展开同一套思路：
  `.nx-inject-body { max-height: 300px; overflow-y: auto; overscroll-behavior: contain; }`，
  并在 `desiredHeight()` 里把「已展开」视为 chrome 的上限而非无界增长。
- 验收：`--expand-inject` 下 `docOverflow` 必须为 0，且 `headerTop` 恒为 28。

## 发现 2（P1，待评估）：亮色下作用域色条区分度弱

亮色四种作用域里「本项目」用 amber-700、「跨项目」用 green-900，在 3px 细条上肉眼接近深灰/墨绿。
无障碍专家此前的意见（作用域不能只靠颜色）已经用 `sr-only` 文本兜底，但**视觉上仍需一个非颜色的区分**：
建议下一批给色条加宽度或形状差异（例如跨项目 3px、本项目 5px），成本极低。

## 发现 3（无问题，作为已验证记录）

选中/批量、长记忆展开、宽屏、亮色、大字号、宿主拒绝长高六种状态下均无溢出、无位移、无遮挡。
